## 借鉴方式与许可证

借鉴 Grocy 的“批次库存 → 消费 → 剩余”和 Mealie 的“自有菜谱 → 所需食材 → 购物需求”产品组织方式，**全部独立实现**。未复制/翻译源码、测试、图标、页面、配方数据，也未引入二者为依赖。因此此目录原创代码使用自身 MIT 许可证；不把 Mealie 的 AGPL 代码改标 MIT。若未来实际复用，应另保留上游声明并履行对应许可，不能沿用当前“未复用”的说明。

## 已落地的实用变化

1. **来源与不确定性直接影响执行。** `core.py` 校验标签/记录/确认/菜谱的引用种类；缺计划日期、同类日期冲突、未来记录、经过标签约束或用户未确认都会保留待核查，不能只靠一个“没过期”标记获得消费权限。
2. **一次使用成为完整账本操作。** `store.py` 在 SQLite 同一事务内重算门禁、跨批次分配、全量扣减并写回执与审计；版本避免旧预览消费，相同幂等意图只生成一次扣减。调用失败时重试原键可恢复结果。
3. **补货与核查分开。** 输出可分配缺口和实物数量缺口；缺开封说明的已有牛奶不会直接当作零库存推销补货，也不会被默认为可使用。
4. **自然语言模型选择被余额和来源限制。** 可选本地 Ollama 接口以 JSON Schema 给出合格菜谱 ID 集合，拒绝未知/被排除/缺货 ID、附加安全声明或数量修改；推理后再次核验快照。规则本身不冒充 AI。

验证命令为 `python3 scripts/check.py`。26 项本地测试覆盖真正的失败/恢复边界：日期时区、开封边界、类型/来源、十进制、并发旧预览、消费回滚、重放、人工核查、HTTP 鉴权/禁回填时间、模型越权和代理/重定向。独立只读审查还在临时数据库验证了相同键 12 并发一次扣减和故意审计失败后的原子回滚；不修改源码。模型测试使用受控假响应和本地假服务，**没有真实模型推理结果**。
